# 密钥和凭据明文修复文档

## 问题是什么

项目中存在数据库、消息队列、JWT、微信小程序、LLM API 等凭据明文写入仓库的情况。典型位置包括：

- `mall-auth-service/src/main/resources/application.yml`
- `mall-order-service/src/main/resources/application.yml`
- `mall-marketing-service/src/main/resources/application.yml`
- `shopkeeper-agent/.env`
- `shopkeeper-agent/conf/app_config.yaml`

这些文件包含或默认包含 MySQL root 密码、RabbitMQ 账号密码、JWT secret、微信 app secret、LLM API key 等敏感信息。

## 影响

- 仓库一旦共享、推送或打包，凭据就会泄露。
- 泄露的 JWT secret 可被用于伪造用户 token。
- 泄露的数据库和 RabbitMQ 凭据可导致业务数据被读取、篡改或清空。
- 泄露的 LLM API key 会产生不可控调用成本。

## 怎么修复

### 1. 立即轮换已暴露密钥

所有已经写入仓库的真实密钥都视为泄露，优先轮换：

- MySQL root 密码
- RabbitMQ `admin` 密码
- `mall.jwt.secret`
- 微信小程序 `secret`
- LLM API key
- 微信支付相关私钥、API v3 key、商户证书序列号

### 2. 配置改为环境变量

将 `application.yml` 中的明文配置改成环境变量占位。

示例：

```yaml
spring:
  datasource:
    url: ${MALL_DB_URL:jdbc:mysql://localhost:3306/mall?useUnicode=true&characterEncoding=UTF-8&useSSL=false&serverTimezone=Asia/Shanghai}
    username: ${MALL_DB_USERNAME:mall_app}
    password: ${MALL_DB_PASSWORD:}
  rabbitmq:
    username: ${RABBITMQ_USERNAME:mall_app}
    password: ${RABBITMQ_PASSWORD:}

mall:
  jwt:
    secret: ${MALL_JWT_SECRET:}
  wechat:
    appid: ${WECHAT_APPID:}
    secret: ${WECHAT_SECRET:}
```

Python 配置保持 `${oc.env:NAME}` 风格，但不要给真实密码默认值：

```yaml
db_dw:
  user: ${oc.env:DB_DW_USER, mall_readonly}
  password: ${oc.env:DB_DW_PASSWORD}

llm:
  api_key: ${oc.env:LLM_API_KEY}
```

### 3. 提供安全的示例文件

保留 `.env.example`，只写假值：

```env
LLM_API_KEY=replace-me
DB_DW_PASSWORD=replace-me
MALL_JWT_SECRET=replace-me-with-32-bytes-minimum
```

确保 `.env` 已加入 `.gitignore`。

### 4. 限制数据库账号权限

不要让业务服务使用 MySQL `root`。建议拆分账号：

- `mall_app`：业务服务使用，可读写 `mall`，不允许 DDL。
- `mall_readonly`：AI 查询使用，只允许 `SELECT`。
- `mall_meta`：AI 元数据构建使用，只允许读写 `meta`。

示例：

```sql
CREATE USER 'mall_readonly'@'%' IDENTIFIED BY 'strong-password';
GRANT SELECT ON mall.* TO 'mall_readonly'@'%';
```

## 验证方式

1. 执行敏感词扫描：

```powershell
rg --line-number "password:|secret:|api_key|sk-|root|123456" .
```

2. 确认结果中只有示例占位值，没有真实密钥。
3. 使用环境变量启动服务，确认配置能正常加载。
4. 用已轮换的旧密钥尝试调用，应全部失败。
