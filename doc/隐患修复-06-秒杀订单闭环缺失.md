# 秒杀订单闭环缺失修复文档

## 问题是什么

当前秒杀 MQ 消费成功后只创建 `seckill_order` 凭证并扣减 `seckill_sku.remain_stock`，没有创建真实业务订单。代码注释中说明由前端拿到秒杀成功凭证后再走 `POST /orders` 创建业务订单。

这导致秒杀成功与订单创建之间存在断点。

## 影响

- 用户秒杀成功但不继续下单，会长期占用秒杀库存。
- 前端重复调用 `/orders` 可能创建重复业务订单。
- 订单服务当前创建订单时扣普通 `product_sku.inventory`，没有消费秒杀凭证。
- 秒杀价、订单价、库存扣减可能不一致。
- 超时未支付后，秒杀库存和凭证状态缺少统一回滚链路。

## 怎么修复

### 1. 明确推荐架构

推荐后端闭环方案：

1. 秒杀入口只负责 Redis 原子扣减和 MQ 入队。
2. MQ 消费端在一个事务中创建真实业务订单。
3. 创建订单时使用秒杀价、秒杀库存、秒杀凭证。
4. 返回给前端的是订单 ID 或排队状态。
5. 前端只查询结果，不参与二段下单。

### 2. `seckill_order` 增加业务订单关联

字段已有 `order_no`，建议补充 `order_id`：

```sql
ALTER TABLE seckill_order
ADD COLUMN order_id BIGINT UNSIGNED DEFAULT NULL COMMENT '业务订单ID',
ADD UNIQUE KEY uk_seckill_order_id(order_id);
```

### 3. 订单服务提供内部秒杀下单接口

新增内部接口，只允许营销服务调用：

```http
POST /internal/orders/seckill
```

请求体：

```json
{
  "seckillOrderId": 1,
  "seckillId": 1,
  "seckillSkuId": 1,
  "skuId": 2,
  "productId": 1,
  "userId": 10001,
  "quantity": 1,
  "seckillPrice": 99.00
}
```

订单服务内部逻辑：

- 不再扣普通商品库存，秒杀库存已在营销域扣减。
- 使用 `seckillPrice` 作为订单明细价格。
- 创建待支付订单。
- 发送订单超时取消消息。
- 返回 `orderId` 和 `orderNo`。

### 4. MQ 消费端回填订单号

`SeckillOrderConsumer` 调用订单服务成功后：

```java
seckillOrderMapper.markOrdered(order.getId(), orderNo);
```

建议改为同时回填 `orderId`：

```sql
UPDATE seckill_order
SET order_id = ?, order_no = ?, status = 1
WHERE id = ? AND status = 0;
```

### 5. 支付超时取消要通知营销域回滚

订单超时取消后，订单服务应通知营销服务：

```http
POST /internal/seckill/orders/{orderNo}/cancel
```

营销服务处理：

- `seckill_order.status` 从 1 改为 3。
- `seckill_sku.remain_stock += quantity`。
- Redis SKU 库存 `+ quantity`。
- 从已购用户集合移除该用户，是否允许重新秒杀由业务规则决定。

### 6. 增加秒杀结果查询接口

前端只轮询：

```http
GET /seckill/{id}/result?skuId=xxx
```

返回：

```json
{
  "status": "pending|ordered|failed|cancelled",
  "orderId": "123",
  "orderNo": "202607..."
}
```

## 验证方式

1. 秒杀成功后，即使前端不再发起 `/orders`，后台也能生成待支付订单。
2. 同一用户重复秒杀同一活动，不会生成重复业务订单。
3. 订单超时取消后，秒杀库存按规则回滚。
4. 秒杀价进入订单明细和支付金额，不使用普通 SKU 原价。
5. MQ 重复投递时，`seckill_order` 和业务订单都保持幂等。
