# 支付链路安全修复文档

## 问题是什么

支付模块存在三类高风险点：

- 微信支付回调 `/pay/wx/notify` 被网关白名单放行，但当前实现跳过微信平台签名验证。
- 回调入账时没有校验回调金额与本地支付记录金额是否一致。
- 默认支付模式是 `mock`，并且订单模块暴露 `PUT /orders/{id}/pay` 直接标记已支付。

这些能力对开发调试方便，但如果进入生产环境，会形成资金安全风险。

## 影响

- 伪造回调可能导致未付款订单被标记为已支付。
- 小金额支付回调可能被用于入账大金额订单。
- mock 支付或手动支付接口误暴露后，用户可绕过真实支付。
- 回调重复、乱序或异常时，支付记录和订单状态可能不一致。

## 怎么修复

### 1. 生产环境禁用 mock 支付

将 `mall.pay.mode` 改为必须显式配置，不允许缺省启用 mock：

```java
@Bean
@ConditionalOnProperty(prefix = "mall.pay", name = "mode", havingValue = "mock")
public PayService mockPayService() {
    return new MockPayService();
}
```

增加启动保护：

```java
@PostConstruct
public void validatePayMode() {
    if ("prod".equals(activeProfile) && "mock".equals(payMode)) {
        throw new IllegalStateException("生产环境禁止使用 mock 支付");
    }
}
```

### 2. 限制手动标记支付接口

`PUT /orders/{id}/pay` 只能用于开发或测试。生产处理方式：

- 删除该接口；或
- 仅在 `dev/test` profile 注册；或
- 改为后台管理员接口，并要求管理员权限、二次确认、操作审计。

推荐：

```java
@Profile({"dev", "test"})
@PutMapping("/{id}/pay")
public Result<Map<String, Object>> pay(...) {
    ...
}
```

### 3. 实现微信支付回调签名验证

处理回调前必须验证以下请求头：

- `Wechatpay-Timestamp`
- `Wechatpay-Nonce`
- `Wechatpay-Signature`
- `Wechatpay-Serial`

验证步骤：

1. 使用商户 API v3 密钥解密回调 resource。
2. 下载并缓存微信支付平台证书。
3. 根据 `Wechatpay-Serial` 找到平台证书。
4. 用平台公钥验签 `timestamp + "\n" + nonce + "\n" + body + "\n"`。
5. 验签失败直接返回失败，不入账。

### 4. 入账前校验金额和订单号

`handleNotify()` 中解析 `amount.total` 后，必须与 `pay_record.pay_amount` 比较：

```java
int expectedCents = record.getPayAmount()
        .multiply(BigDecimal.valueOf(100))
        .setScale(0, RoundingMode.HALF_UP)
        .intValueExact();

if (notifyResult.getAmountTotal() != expectedCents) {
    throw new BizException(ResultCode.PAY_NOTIFY_VERIFY_FAILED.getCode(), "支付金额不一致");
}
```

同时校验：

- `out_trade_no` 必须等于本地 `order_no`。
- `mchid` 必须等于本系统商户号。
- `appid` 必须等于本系统小程序 appid。
- `trade_state` 只能在 `SUCCESS` 时入账。

### 5. 增加入账幂等保护

使用条件更新避免并发重复入账：

```sql
UPDATE pay_record
SET pay_status = 1,
    transaction_id = ?,
    paid_at = NOW()
WHERE id = ?
  AND pay_status = 0;
```

只有更新行数为 1 时才推进订单状态。

### 6. 记录支付审计日志

记录以下字段：

- orderNo
- transactionId
- amountTotal
- request headers
- raw callback body hash
- verify result
-入账前后状态

不要完整记录敏感密钥或完整证书内容。

## 验证方式

1. 生产 profile 下 `mall.pay.mode=mock` 应启动失败。
2. 无签名、错误签名、错误序列号的回调都不能入账。
3. 金额不一致的回调不能入账。
4. 重复回调只入账一次。
5. `PUT /orders/{id}/pay` 在生产环境不可访问。
