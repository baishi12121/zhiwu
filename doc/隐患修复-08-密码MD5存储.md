# 密码 MD5 存储修复文档

## 问题是什么

认证服务当前使用 MD5 保存和校验用户密码。登录时对明文密码做 MD5 后和数据库比对，注册时也直接保存 MD5。

MD5 不适合存储密码，因为计算速度快、无盐、容易被彩虹表和暴力破解攻击。

## 影响

- 数据库泄露后，用户密码很容易被破解。
- 相同密码会得到相同 hash，攻击者能快速识别弱密码用户。
- 不符合生产系统常见安全要求。

## 怎么修复

### 1. 引入 BCrypt

在认证服务中使用 Spring Security Crypto：

```xml
<dependency>
    <groupId>org.springframework.security</groupId>
    <artifactId>spring-security-crypto</artifactId>
</dependency>
```

注册 Bean：

```java
@Bean
public PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder(12);
}
```

### 2. 注册时保存 BCrypt

替换：

```java
DigestUtils.md5DigestAsHex(req.getPassword().getBytes(StandardCharsets.UTF_8))
```

为：

```java
passwordEncoder.encode(req.getPassword())
```

### 3. 登录时兼容旧 MD5 并自动升级

为了兼容已有种子数据和老用户，可采用双格式校验：

```java
private boolean matchesPassword(String rawPassword, User user) {
    String stored = user.getPassword();
    if (stored == null || stored.isBlank()) {
        return false;
    }

    if (stored.startsWith("$2a$") || stored.startsWith("$2b$") || stored.startsWith("$2y$")) {
        return passwordEncoder.matches(rawPassword, stored);
    }

    String md5 = DigestUtils.md5DigestAsHex(rawPassword.getBytes(StandardCharsets.UTF_8));
    if (md5.equalsIgnoreCase(stored)) {
        user.setPassword(passwordEncoder.encode(rawPassword));
        userMapper.updateById(user);
        return true;
    }

    return false;
}
```

### 4. 修改数据库注释

将 `user.password` 注释从 `MD5 密文` 改为：

```sql
COMMENT '密码哈希，BCrypt格式；历史数据可能为MD5，登录后自动升级'
```

### 5. 清理 `user_auth.credential`

如果密码统一存放在 `user.password`，`user_auth.credential` 不应再保存密码 hash。建议：

- USERNAME 凭证只保留账号标识。
- PHONE 凭证只保留手机号标识。
- WECHAT 凭证保存 openid/session 相关标识时注意加密或最小化保存。

### 6. 增加密码策略

注册和改密时校验：

- 长度至少 8 位。
- 不允许纯数字 6 位弱密码。
- 不允许与手机号、账号相同。

## 验证方式

1. 新注册用户的 `password` 字段以 `$2a$`、`$2b$` 或 `$2y$` 开头。
2. 老 MD5 用户可以登录。
3. 老 MD5 用户登录成功后，数据库中的密码自动升级为 BCrypt。
4. 错误密码不能登录。
5. 弱密码注册被拒绝。
