## 秒杀设计速查（实现时以此为准）

### 服务边界（集中式）
全部在 `mall-seckill-service`(8089)：秒杀入口/预热/本地消息表/MQ 消费/订单创建/超时取消/库存回补。网关 `/seckill/**` 已路由到本服务。与 order-service 仅两处协作：支付走 order-service `/pay/**`（共用 order 表）；用户取消秒杀订单时 order-service Feign 调本服务 `/internal/seckill/orders/{orderNo}/cancel` 回补。

### Redis Key（全部带 `mall:` 前缀）
```
mall:seckill:stock:{activityId}:{seckillItemId}        # 整型库存（预热写入，Lua DECRBY）
mall:seckill:item:{seckillItemId}                      # 商品项元数据（spu/sku/秒杀价/原价/limit，预热写入，TTL=活动剩余时长）
mall:seckill:user:{activityId}:{seckillItemId}:{userId} # 累计已购数量（Lua INCRBY，TTL=活动剩余时长兜底30min）
mall:seckill:order:{userId}:{activityId}:{seckillItemId} # 消费幂等状态机，值 1PROCESSING 2SUCCESS 3FAILED，TTL 30min
```

### Lua 原子扣减（3.4.2 节，`RedisScript<Long>` 静态加载）
```
KEYS[1]=stock  KEYS[2]=user
ARGV[1]=限购Key TTL(秒)  ARGV[2]=quantity  ARGV[3]=limit_per_user
逻辑：quantity<1 → -2；已购+quantity>limit → -1；库存<quantity → 0；否则 DECRBY stock、INCRBY user+EXPIRE、返回 1
```

### MQ 拓扑
```
seckill.exchange (Direct, durable)  →  seckill.order.queue (durable, x-delivery-limit=3)   routingKey=seckill.order
seckill.delay.exchange (x-delayed-message)  →  seckill.delay.queue  (支付超时取消，与 order-service 的 order.delay.* 相互独立)
```
开启 `publisher-confirm-type: correlated` + `publisher-returns: true`；消费端手动 ACK。

### 本地消息表 mq_message（状态机）
`status`：0 待扣库存 → 1 待发送 → 2 已发送（Confirm ACK）→ 4 已完成（订单创建成功）；3 发送失败。`message_id`=业务 messageId（唯一）。字段：`seckill_item_id`/`spu_id`/`sku_id`/`quantity`（SKU 维度）。

### 核心流程
- **execute**：读 `seckill:item` 元数据 → 活动窗口校验（`seckill_activity.start_time/end_time`）→ **先写 mq_message(0 待扣库存)** → Lua → 成功：置 1 待发送 + 发 MQ（Confirm 后置 2）；失败：置 3 发送失败并返回对应错误。
- **消费者**：SETNX `seckill:order`=PROCESSING → 事务建单（`order` + `order_item`，扣 `seckill_item.seckill_stock`，回写 `mq_message`=4）→ 置 SUCCESS → ACK；`DuplicateKeyException` → 视为成功直接 ACK；其它异常 → 置 FAILED + 重投上限。
- **超时取消**：建单成功即发 `seckill.delay.queue`（`x-delay`=支付超时毫秒）；消费时 `order_state==1` → 置 6 + 回补库存（Redis+DB 双写）。
- **结果查询**：以 `mq_message.status` 为来源（0/1/2→pending，4→ordered 并从 order 表按 `uk_user_activity_item` 查 orderId/orderNo，3→failed）。

### 库表（见 sql/init.sql）
`seckill_activity`、`seckill_item`（`uk_activity_sku(activity_id,sku_id)`）、`mq_message`、`order`（含 `order_source`/`activity_id`/`seckill_item_id` + `uk_user_activity_item`）、`order_item`（`cur_price`=秒杀价快照）、`seckill_stock_compensate`（Phase 2 用）。

### 接口契约
```
POST /seckill/{activityId}/execute   body {seckillItemId, quantity, addressId}
   200 → {status:"queued", messageId:"userId:activityId:seckillItemId"}
   4001 库存不足 / 4002 您已购买过该商品 / 4003 活动未开始或已结束
GET  /seckill/{activityId}/result?seckillItemId=
   → {status:"pending|ordered|failed", orderId, orderNo}
POST /internal/seckill/orders/{orderNo}/cancel   body {activityId, seckillItemId, userId, quantity}
   → 回补 Redis 库存 + seckill_item.seckill_stock（幂等）
```

## 关键陷阱（写代码时务必避开）

1. **Lua 整型**：库存/限购 Key 用 `StringRedisTemplate`，别用 value 为 JSON 的 `RedisTemplate`。
2. **禁止对 order/order_item 做 DDL**：只做字段映射，字段以 init.sql 为准。
3. **先写消息表、后扣库存**：execute 顺序不可颠倒（可靠投递凭证）。
4. **结果查询不要用 Redis 幂等 Key 当状态来源**（它消费时才创建），用 `mq_message.status`。
5. **Redis Key 别漏 `mall:` 前缀**；模板常量进 `SeckillConstants`，勿散落硬编码。
6. **`/internal/**` 要进 `mall.security.exclude-paths` 白名单**（Feign 直连不校验；网关已拦外部访问）。
7. `mall.jwt.secret` 必须与网关一致（≥32 字节），否则自校验验签失败。
8. 8089 端口：调试时不要同时跑 shopkeeper-agent 的 TEI 容器。
