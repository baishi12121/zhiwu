# 任务 03：秒杀入口与本地消息表

> 目标：实现秒杀入口 `execute`/`result`、Redis 预热、本地消息表 `mq_message` 写入与状态流转、MQ 发送 + Publisher Confirm。**本任务不写订单创建（在任务 04）。**

## 前置
- 任务 02 完成（实体/Mapper/常量/Lua/MQ 声明）
- 权威细节：`doc/秒杀方案分阶段实施计划.md` 3.4.4 接口契约、3.3 功能范围

## 规格

### 1. controller/SeckillController（路径 `/seckill/**`，经网关，token 由自动装配的拦截器校验）
```java
@RestController
@RequestMapping("/seckill")
public class SeckillController {
    @PostMapping("/{activityId}/execute")   // 请求头 X-User-Id 由网关注入（可信来源）
    Result<ExecuteResultDTO> execute(@PathVariable Long activityId,
                                     @Valid @RequestBody ExecuteReqDTO req);

    @GetMapping("/{activityId}/result")
    Result<SeckillResultDTO> result(@PathVariable Long activityId,
                                    @RequestParam Long seckillItemId);
}
```
- `ExecuteReqDTO`：`seckillItemId`(必填)、`quantity`(默认1, min=1, max=99)、`addressId`(必填，待确认项 3 默认方案)
- 当前用户 ID 来源：**优先 `LoginUserContext`（mall-common-web，网关注入 X-User-Id）**；若为空可回退解析 token 里的 userId。**不要信任请求体里的 userId。**

### 2. service/SeckillApplicationService（编排）
**预热 `warmUp()`**：
- 查启用且在活动窗口内的活动及其 `seckill_item`（status=1）
- 逐 item：`seckill:stock` 写 `seckill_stock`；`seckill:item` 写元数据 JSON（spuId/skuId/seckillPrice/price/limitPerUser/activityId），TTL=活动剩余时长
- 触发：`ApplicationRunner` 启动时 + `@Scheduled` 每分钟扫即将开始的活动；可加一个手动触发的 admin 内部接口（可选）
- 幂等：重复预热直接覆盖

**execute(activityId, req)**（顺序**不可变**）：
1. 校验活动窗口：读 `seckill_activity`（可缓存到 Redis），`now` 不在 `[start_time,end_time]` → `BizException(4003 活动未开始或已结束)`
2. 组装业务 `messageId = userId:activityId:seckillItemId`
3. **先写本地消息表**：`INSERT mq_message`（status=0 待扣库存，message_id=messageId，user_id/activity_id/seckill_item_id/spu_id/sku_id/quantity 从 `seckill:item` 元数据补齐）；`DuplicateKeyException`（uk_message_id）→ 说明已处理过，直接返回 queued + 该 messageId
4. Lua 扣库存：`SeckillStockRedis.tryDeduct(...)`，`limitPerUser` 从元数据读
   - 返回 1 → `UPDATE mq_message SET status=1 待发送`，然后**发 MQ**（见下）
   - 返回 0 → 置 status=3 发送失败 + `BizException(4001 库存不足)`
   - 返回 -1 → 置 status=3 + `BizException(4002 您已购买过该商品)`
   - 返回 -2 → 置 status=3 + `BizException(参数错误)`
5. 返回 `{ status:"queued", messageId }`

**发 MQ + Confirm**（MqMessageService）：
- 消息体 = 完整快照 DTO（messageId/userId/activityId/seckillItemId/spuId/skuId/seckillPrice/price/quantity/addressId）
- `rabbitTemplate.convertAndSend(seckill.exchange, seckill.order, 消息, msg -> { DeliveryMode.PERSISTENT })`
- Confirm 回调（在 `SeckillMqConfig` 里接入）：ACK → 该 messageId 的 mq_message 置 2 已发送；NACK → 保持 1 待发送（由补偿任务重投）

**result(activityId, seckillItemId)**：
- 查 `mq_message` by message_id（当前用户）
- status ∈ {0,1,2} → `{status:"pending"}`；status=4 → `{status:"ordered", orderId, orderNo}`（order 表按 `uk_user_activity_item(user_id, activity_id, seckill_item_id)` 查）；status=3 → `{status:"failed"}`
- 无记录 → 抛"未参与秒杀"或返回 pending（按业务定）

### 3. service/MqMessageService
- `createPending(messageId, dto)`：写 status=0
- `markSending(messageId)` / `markSent(messageId)`（Confirm ACK 用）/ `markFailed(messageId)` / `markDone(messageId)`
- `retryExpired(batchSize)`：扫 status=1 且 `next_retry_time<=now` 的记录重投（供补偿任务用）
- 全部按 `message_id` 精确更新

### 4. service/SeckillTask（@Scheduled）
- 每 30s 调 `retryExpired(200)`：重投待发送消息（发 MQ 同 execute 步骤），失败则 `retry_count++`、`next_retry_time = now + 2^retry_count`（封顶 30min），`retry_count>3` 置 status=3 发送失败
- Phase 1 单实例，先不加分布式锁（注释说明即可）

## 硬性约束
- execute 顺序：**活动窗口 → 写消息表 → Lua → 发 MQ**，不可颠倒。
- 库存/限购 Key 走 `StringRedisTemplate`。
- 结果查询用 `mq_message.status`，**不用** Redis 幂等 Key。
- 错误码 4001/4002/4003 对应文案固定（见 00 接口契约）。

## 完成标准 / 自测
- `mvn clean compile` 通过；服务启动成功。
- 造一个可秒杀的 activity+item（`sql/init.sql` 已带 seed：activity 1、item 1/2），手动 `execute`：
  - 窗口内成功 → 返回 queued + messageId；`mq_message` 出现一行（先 0→1→2）
  - 重复 execute 同 user/item → 4002
  - 库存耗尽 → 4001
- 汇报：execute 全流程日志（含 mq_message 状态流转、Confirm 结果）、result 查询结果。
