# 任务 07：构建验证与验收

> 目标：全链路联调 + 验收项核验。确认秒杀闭环（execute → MQ → 建单 → 超时取消回补）正确，且满足无超卖 / 无重复订单 / 无丢消息。

## 前置
- 任务 01~06 全部完成
- 前置服务：Nacos、MySQL、Redis、RabbitMQ（含延迟插件）、网关、auth/user/order/seckill 服务均已启动

## 环境准备
- 秒杀 seed 数据已就位（`sql/init.sql` / `_apply_seckill_v2.sql` 已含 activity 1「周年庆秒杀」+ item 1/2，窗口覆盖当前时间）
- 确认网关 `/seckill/**` → `lb://mall-seckill-service`；`/orders/**` → order-service
- 用 `POST /auth/login` 拿一个用户 token（如 admin/123456）

## 验收清单（对照 `doc/秒杀方案分阶段实施计划.md` 3.5）

| # | 验收项 | 做法 | 预期 |
|---|---|---|---|
| 1 | 秒杀成功链路 | `POST /seckill/1/execute`（带 token，seckillItemId=1, quantity=1, addressId） | 返回 queued+messageId；几秒后 `order`+`order_item` 出现秒杀单（order_source=2）、`mq_message.status=4` |
| 2 | 重复秒杀 | 同用户同 item 再 execute | 4002「您已购买过该商品」 |
| 3 | 活动窗口 | 把 activity 时间改成过去/未来（或直接改库）再 execute | 4003「活动未开始或已结束」 |
| 4 | 无重复订单 | 手动向 `seckill.order.queue` 重投同一 messageId 3 次 | 订单表仅 1 行（Redis SUCCESS 拦截或唯一键兜底） |
| 5 | 库存正确 | 压测后对账：`seckill_item.seckill_stock` + 秒杀订单数 = 初始库存；Redis `mall:seckill:stock:*` 与 DB 一致 | 等式成立 |
| 6 | 无超卖 | 并发压测：500 请求抢 100 库存 | 订单数 = 100，无 0 库存后仍下单 |
| 7 | 无丢消息 | kill seckill-service → 重启 | 重启后补偿任务把待发送消息重投，订单最终落库 |
| 8 | 支付超时取消 | 建单后不支付，等超时（或投延迟消息/触发兜底扫描） | 订单置 6 已取消，库存 Redis+DB 回补 |
| 9 | 用户取消回补 | 建秒杀单 → 走 order-service 用户取消 | 订单置 6，seckill-service 收到内部调用并回补库存 |
| 10 | 结果查询 | `GET /seckill/1/result?seckillItemId=1` | pending（未消费完）/ ordered（带 orderId,orderNo）/ failed（发送失败）三态正确 |

## 压测（500 QPS）
- 用 JMeter 或 `ab` 对 `POST /seckill/1/execute` 压 500 并发 / 库存 100
- 关注：P99 < 800ms、无 500、无超卖（订单数=库存）、`mq_message` 无 status=3 大量堆积
- 压测前把 Redis `mall:seckill:stock:*` 与 `seckill_item.seckill_stock` 重置一致；压测后对账

## 常见问题排查
- **建单慢/不消费**：查 `seckill.order.queue` 积压、消费者日志、`mq_message.status` 卡在哪一步
- **Lua 报错**：确认库存/限购 Key 走 `StringRedisTemplate`（JSON 序列化会导致 DECRBY 失败）
- **验签失败 401**：`mall.jwt.secret` 与网关不一致
- **超时取消不触发**：确认延迟插件已装、`x-delay` 头生效、`seckill.delay.queue` 有消费者
