# 任务 02：数据层与基础设施

> 目标：把任务 01 搭好的空壳填充到「有实体、有 Mapper、有常量、有 Lua、有 MQ 声明」的程度，为后续业务逻辑铺路。本任务不写秒杀业务编排。

## 前置
- 任务 01 完成（可编译可启动）
- 字段以 `sql/init.sql` 为准

## 规格（包根：`com.hyf.mallseckillservice`）

### 1. entity/（Lombok @Data，DB 表实体继承 `BaseEntity`（id/createTime/updateTime），照 order-service 的实体写法）
- `SeckillActivityDO` ← `seckill_activity`（id/name/start_time/end_time/enabled/remark）
- `SeckillItemDO` ← `seckill_item`（id/activity_id/spu_id/sku_id/seckill_price/seckill_stock/limit_per_user/sort_order/status）
- `MqMessageDO` ← `mq_message`（id/message_id/user_id/activity_id/**seckill_item_id**/spu_id/sku_id/quantity/status/retry_count/next_retry_time）
- `OrderDO` ← `order`（**完整字段映射**，含 order_source/activity_id/seckill_item_id/address_snapshot 等，照 order-service 的 OrderDO 抄字段但放本服务包）
- `OrderItemDO` ← `order_item`（order_id/sku_id/spu_id/name/image/attrs_text/cur_price/price/quantity/subtotal/real_pay/properties）

### 2. mapper/ + `resources/mapper/*.xml`
- `SeckillActivityMapper` / `SeckillItemMapper` / `MqMessageMapper` / `OrderMapper` / `OrderItemMapper`
- MyBatis-Plus 继承 `BaseMapper<T>`；复杂 SQL（扣库存、幂等回写、状态扫描）用 XML
- **关键 SQL**（XML）：
  - 扣库存（DB 最后防线，供建单事务用）：
    ```sql
    UPDATE seckill_item SET seckill_stock = seckill_stock - #{quantity}
    WHERE id = #{id} AND seckill_stock >= #{quantity}
    ```
  - 回补库存：`UPDATE seckill_item SET seckill_stock = seckill_stock + #{quantity} WHERE id = #{id}`
  - 补偿扫描：`SELECT * FROM mq_message WHERE status = 1 AND (next_retry_time IS NULL OR next_retry_time <= NOW()) LIMIT 200`

### 4. redis/SeckillStockRedis（Lua 执行器）
- `private static final RedisScript<Long> DECREMENT_SCRIPT = RedisScript.of(脚本字符串, Long.class);` 静态加载一次
- Lua 脚本内容（任务 00 的 Lua 语义）：
  ```
  local bought = tonumber(redis.call('GET', KEYS[2]))
  if bought and bought + tonumber(ARGV[2]) > tonumber(ARGV[3]) then return -1 end
  local stock = tonumber(redis.call('GET', KEYS[1]))
  if not stock or stock < tonumber(ARGV[2]) then return 0 end
  redis.call('DECRBY', KEYS[1], ARGV[2])
  redis.call('INCRBY', KEYS[2], ARGV[2])
  redis.call('EXPIRE', KEYS[2], ARGV[1])
  return 1
  ```
- 注入 `StringRedisTemplate`（**必须是 StringRedisTemplate**），提供：
  - `long tryDeduct(activityId, seckillItemId, userId, quantity, limitPerUser, ttl)`：执行 Lua，返回 1/0/-1/-2
  - `void restoreStock(activityId, seckillItemId, quantity)`：`INCRBY` 库存
  - `void warmUpStock(activityId, seckillItemId, stock)`：`SET stock`（活动开始前预热）
  - `void cacheItemMeta(seckillItemId, json, ttl)` / `String getItemMeta(seckillItemId)`：商品项元数据读写

### 5. config/SeckillMqConfig
声明 `seckill.exchange`（`TopicExchange` 或 `DirectExchange`，durable）→ `seckill.order.queue`（durable，**声明参数加 `x-delivery-limit=3`**）→ 绑定 `seckill.order`。注入 `RabbitTemplate` 设置：
- `setMandatory(true)`
- `setConfirmCallback((correlationData, ack, cause) -> ...)`（回调逻辑在任务 03 接入 MqMessageService）
- `setReturnsCallback(...)` 处理不可路由（记日志）

### 6. config/SeckillDelayConfig
照 `mall-order-service/mq/RabbitMQDelayedConfig` 抄一份：`CustomExchange("seckill.delay.exchange", "x-delayed-message", durable)` + `Queue("seckill.delay.queue", durable)` + 绑定 `seckill.delay.routing`。**不要**复用 order-service 的队列名（相互独立）。

## 硬性约束
- **禁止对 order/order_item 做 DDL**；`OrderDO`/`OrderItemDO` 只做字段映射。
- 库存/限购相关一律走 `StringRedisTemplate`。
- 常量不硬编码、不重复造 `MallConstants` 已有的。
