# 秒杀压测结果报告（2026-08-13）

## 1. 测试目标

验证秒杀链路在 `500` 个并发请求抢 `100` 件库存场景下的库存一致性、订单一致性和接口性能表现。

压测链路：

```text
客户端压测脚本 -> mall-gateway-service(8080) -> mall-seckill-service(8089) -> Redis Lua 扣库存 -> RabbitMQ -> 异步创建订单 -> MySQL
```

## 3. 执行说明

直接运行原脚本时，当前 shell 未设置 `MALL_JWT_SECRET`，脚本使用默认密钥离线签发 JWT，导致网关鉴权失败：

```text
总请求: 500
auth(未认证): 500
```

该轮请求没有进入秒杀业务逻辑，因此不作为有效压测结果。

随后使用 `/auth/login` 获取服务端真实签发的 accessToken，再执行同等规模压测。为支持真实登录，仅对压测用户段 `2000000~2000499` 补齐了测试密码和 `PHONE` 登录凭证。

## 6. 验收结论

| 验收项 | 结果 | 明细 |
| --- | --- | --- |
| 无超卖 | PASS | `订单数 100 <= 初始库存 100` |
| DB 扣减等于订单数 | PASS | `100 == 100` |
| 订单数等于 MQ 完成数 | PASS | `100 == 100` |
| Redis 扣减等于订单数 | PASS | `100 == 100` |
| 无重复订单 | PASS | `订单数 100 == 去重订单数 100` |

库存一致性、订单一致性、MQ 消费结果均通过验收；本轮压测未出现超卖或重复订单。

性能方面，本次有效压测 QPS 为 `191`，P99 延迟为 `2529ms`。对照脚本注释中的目标 `单机 500 QPS / P99 < 800ms`，当前环境下性能指标未达标，需要继续排查网关、秒杀服务、Redis、RabbitMQ、MySQL 写入和异步消费链路的耗时瓶颈。
